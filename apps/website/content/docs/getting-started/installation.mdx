## Prerequisites

<DocPrerequisiteGrid
  items={[
    { label: 'Runtime', value: 'Node.js 22.0.0 or newer' },
    { label: 'Package manager', value: 'pnpm, bun, npm, yarn, or deno' },
    { label: 'Editor', value: 'Any — full type definitions ship with every package' },
  ]}
/>

[Download Node.js](https://nodejs.org/) or manage versions with
[nvm](https://github.com/nvm-sh/nvm). NextRush declares `"engines": { "node": ">=22.0.0" }` in
every published package — this isn't a recommendation, it's what the framework is built and
tested against. Examples on this page show all five package managers.

<Callout type="info" title="Why Node.js 22?">
  The framework targets ES2022 and stable ESM throughout — no CommonJS build exists for any
  `@nextrush/*` package. Node 22 is the oldest LTS line where that target lands cleanly, so it's
  the floor every adapter and example assumes. See the [FAQ](/docs/help/faq) for the full
  reasoning.
</Callout>

## Install manually

<div className="install-steps">

<Steps>

<Step>

### Create a project folder

```bash
mkdir my-api && cd my-api
pnpm init
```

Add `"type": "module"` to the generated `package.json`. NextRush is ESM-only — there's no
CommonJS build to fall back to — so Node needs to know your `.ts`/`.js` files are ES modules
before anything else runs.

<p className="not-prose mt-3 flex items-start gap-2 rounded-lg bg-[color-mix(in_srgb,var(--success)_8%,var(--color-fd-card))] px-3 py-2 text-sm font-medium text-[var(--status-success-text)]">
  <span aria-hidden>✅</span>
  <span>Expected result — the folder appears with a <code>package.json</code> containing <code>"type": "module"</code>.</span>
</p>

</Step>

<Step>

### Install NextRush

<PackageInstall packages={['nextrush']} dev={['tsx', 'typescript', '@types/node']} />

**Why it works:**

- `nextrush` is the meta-package — re-exports `@nextrush/core`, `@nextrush/router`, `@nextrush/adapter-node`, `@nextrush/errors`, and `@nextrush/types` in one install
- This single install covers the functional path (`createApp`, `createRouter`, `listen`) with no separate packages to add
- `tsx` runs the TypeScript entry file directly in the next step — no separate compile pass

</Step>

<Step>

### Write a server and run it

Create `src/index.ts`:

```ts title="src/index.ts"
import { createApp, createRouter, listen } from 'nextrush';

const app = createApp();
const router = createRouter();

router.get('/', (ctx) => {
  ctx.json({ status: 'ok', framework: 'NextRush' });
});

app.route('/', router);
await listen(app, 8080);
```

Run it:

```bash
npx tsx src/index.ts
```

<p className="not-prose mt-3 flex items-start gap-2 rounded-lg bg-[color-mix(in_srgb,var(--success)_8%,var(--color-fd-card))] px-3 py-2 text-sm font-medium text-[var(--status-success-text)]">
  <span aria-hidden>✅</span>
  <span>Expected result — a JSON response on <code>http://localhost:8080</code>: <code>{"{"}"status": "ok", "framework": "NextRush"{"}"}</code></span>
</p>

**Why it works:**

- `createApp()` builds the application
- `createRouter()` gives you a router to attach routes to
- `app.route('/', router)` mounts the router
- `listen(app, 8080)` starts the Node adapter

If you see that JSON response, NextRush is installed and serving requests.

</Step>

<Step>

### Configure TypeScript

NextRush ships full type definitions. This `tsconfig.json` matches what the framework's
own examples and CI run against:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "outDir": "dist",
    "rootDir": "src"
  },
  "include": ["src"]
}
```

<Callout type="info" title="Only using class-based controllers?">
  Add `"experimentalDecorators": true` and `"emitDecoratorMetadata": true` to
  `compilerOptions` if you import from `nextrush/class`. That entry point auto-imports
  `reflect-metadata` itself — you don't add it to your own code or dependencies.
</Callout>

</Step>

</Steps>

## Verify everything works

Two checks and you're done — runtime version, then the server responds.

**Check 1 · Runtime**

```bash
node --version
# → v22.x.x or newer
```

If `node --version` reports below 22, install a newer version before continuing — NextRush's
adapters and examples aren't tested against older lines, and package installs may warn or fail
depending on your package manager's `engines` enforcement.

**Check 2 · Server**

```bash
curl http://localhost:8080/
# → {"status":"ok","framework":"NextRush"}
```

<Callout type="info" title="🎉 Installation successful">
  Your request completed the full request path — the same one every NextRush app runs:

  <MentalModelFlow steps={['Application', 'Router', 'Handler', 'Response']} />

  `createApp()` built the application, the router matched `/` to your handler, and the handler
  wrote the response back through `ctx.json()`. Your environment is ready for a real application.
  Everything below this point is optional: pick it up whenever you need it.
</Callout>

## Having trouble?

Most installation issues fall into one of these three categories.

<details>
<summary>⚠ Server won't start; import errors on <code>nextrush</code></summary>

**Cause:** `package.json` is missing `"type": "module"`, so Node tries to load ESM output as
CommonJS.

**Fix:** add `"type": "module"` — NextRush publishes no CommonJS build for any package to fall
back to.

</details>

<details>
<summary>⚠ <code>node --version</code> is below 22</summary>

**Cause:** an older Node install or version manager default.

**Fix:** install/select Node 22 or newer before running `pnpm add nextrush` — the framework's
`engines` field expects it everywhere.

</details>

<details>
<summary>⚠ Decorators throw <code>reflect-metadata</code> errors</summary>

**Cause:** importing `nextrush/class` without `experimentalDecorators`/`emitDecoratorMetadata`
enabled in `tsconfig.json`.

**Fix:** add both compiler options — the `reflect-metadata` import itself is already handled for
you.

</details>
