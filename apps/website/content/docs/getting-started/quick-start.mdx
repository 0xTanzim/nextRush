## Why a Task API

A one-route hello-world stops too early. A Task API forces four backend concerns at once:

- **Storage** — remember state between requests
- **Input** — parse and validate a POST body before you trust it
- **Lookup** — resolve a route param, or fail honestly
- **Errors** — real HTTP `400` / `404`, not silent bugs

Build those four once; Users and Orders reuse the same shape.

### Step 4 — Accept data with `POST`

**How it fits:** reading a body is where the middleware box earns its place.

**This step adds**

- ✓ In-memory `Map` as the store
- ✓ `app.use(json())` **before** the routes
- ✓ `POST /tasks` + `GET /tasks` (replaces the Part 1 `GET /` demo route)

```diff
  const app = createApp();
+ app.use(json());

  const router = createRouter();
+ router.post('/tasks', (ctx) => { ... });
+ router.get('/tasks', (ctx) => { ... });
```

<GuideAccordion icon="folder-tree" iconColor="blue" title="Full src/index.ts after this step" description="The complete file once this step lands.">

```ts title="src/index.ts"
import { createApp, createRouter, listen, BadRequestError } from 'nextrush';
import { json } from '@nextrush/body-parser';

type Task = { id: number; title: string; done: boolean };

const tasks = new Map<number, Task>();
let nextId = 1;

const app = createApp();

// Parse JSON bodies before any route runs — without this, ctx.body stays undefined.
app.use(json());

const router = createRouter();

router.get('/tasks', (ctx) => {
  ctx.json([...tasks.values()]);
});

router.post('/tasks', (ctx) => {
  const body = ctx.body as { title?: string };
  if (!body?.title) throw new BadRequestError('title is required');

  const task: Task = { id: nextId++, title: body.title, done: false };
  tasks.set(task.id, task);

  ctx.status = 201;
  ctx.json(task);
});

app.route('/', router);
await listen(app, 8080);
```

</GuideAccordion>

Restart (`Ctrl+C`, then `npx tsx src/index.ts`), then:

```bash
curl -X POST http://localhost:8080/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Write the docs"}'
# → {"id":1,"title":"Write the docs","done":false}

curl -X POST http://localhost:8080/tasks \
  -H 'Content-Type: application/json' \
  -d '{}'
# → HTTP/1.1 400 Bad Request
```

<WhyItWorks>
  <WhyItem>Order is Adapter → <code>json()</code> fills <code>ctx.body</code> → Router → Handler</WhyItem>
  <WhyItem>Pipeline runs top to bottom — <code>app.use(json())</code> must sit <strong>above</strong> <code>app.route(...)</code></WhyItem>
  <WhyItem><code>createApp()</code> owns middleware; <code>createRouter()</code> only matches paths</WhyItem>
</WhyItWorks>

<Callout type="warn">
If a `POST` handler sees `ctx.body` as `undefined`, the parser ran too late or wasn't registered.
`app.use(json())` has to sit above the router — not inside a handler, not after `app.route(...)`.
</Callout>

**How you know it worked:** a valid POST returns `201` with an `id`. Empty `{}` returns `400`, not a
silent bad record.

### Step 5 — Read it back, or return a real 404

**What changed:** storing only matters if you can fetch — and a miss must not look like success.

**This step adds**

- ✓ `GET /tasks/:id`
- ✓ `NotFoundError` when the lookup misses

```diff
  router.get('/tasks', (ctx) => {
    ctx.json([...tasks.values()]);
  });

+ router.get('/tasks/:id', (ctx) => {
+   const task = tasks.get(Number(ctx.params.id));
+   if (!task) throw new NotFoundError('Task not found');
+   ctx.json(task);
+ });
```

import { createApp, createRouter, listen, BadRequestError, NotFoundError } from 'nextrush';
import { json } from '@nextrush/body-parser';

const tasks = new Map<number, Task>();
let nextId = 1;

const app = createApp();
app.use(json());

## What you learned

Mental models (not the file list):

- **Request pipeline** — Adapter → Middleware → Router → Handler → Context
- **Routing** — params + mount — [Routing](/docs/concepts/routing)
- **Context** — `ctx.body`, `ctx.params`, `ctx.json()`, `ctx.status` — [Context](/docs/concepts/context)
- **Middleware order** — parser before router or `ctx.body` is empty — [Middleware](/docs/concepts/middleware)
- **Errors** — throw `HttpError`, framework maps status — [Error handling](/docs/guides/api-development/error-handling)

A bigger app is this same pipeline with more middleware and more routes — not a different shape.

## 🎓 Think like an architect

You've finished building. Now explain why it works — that's what separates copying from understanding.

<GuideAccordion icon="sparkles" iconColor="blue" title="① Why create a router and mount it with app.route('/', router), rather than adding a route straight to app?">
  `app.route('/', router)` keeps task routes in one module you can test and reuse. Mount at `/api`
  later without rewriting handlers.
</GuideAccordion>

<GuideAccordion icon="sparkles" iconColor="blue" title="② Why does app.use(json()) have to sit above the router instead of inside a handler?">
  `json()` runs for every request before matching. Inside a handler is too late; after
  `app.route(...)` never runs for mounted routes.
</GuideAccordion>

<GuideAccordion icon="sparkles" iconColor="blue" title="③ Why is a thrown NotFoundError better for a missing id than ctx.json(null) with a 200?">
  Callers check status first. A `200` with `null` looks like success to caches, proxies, and client
  libraries that only inspect the status line.
</GuideAccordion>

### Solutions

Peek only after you've tried. Each builds on the previous level.

<details>
<summary>Solution — Starter (DELETE)</summary>

```ts title="src/index.ts (added route)"
router.delete('/tasks/:id', (ctx) => {
  const existed = tasks.delete(Number(ctx.params.id));
  if (!existed) throw new NotFoundError('Task not found');

  ctx.status = 204;
  ctx.send('');
});
```

Same three ideas: `:id`, the store, thrown `NotFoundError`. New detail: `204 No Content`.

```bash
curl -i -X DELETE http://localhost:8080/tasks/1
# → HTTP/1.1 204 No Content

curl -i -X DELETE http://localhost:8080/tasks/999
# → HTTP/1.1 404 Not Found
```

</details>

<details>
<summary>Solution — Intermediate (PUT)</summary>

```ts title="src/index.ts (added route)"
router.put('/tasks/:id', (ctx) => {
  const id = Number(ctx.params.id);
  const existing = tasks.get(id);
  if (!existing) throw new NotFoundError('Task not found');

  const body = ctx.body as { title?: string; done?: boolean };
  if (!body?.title) throw new BadRequestError('title is required');

  const updated: Task = { id, title: body.title, done: body.done ?? existing.done };
  tasks.set(id, updated);
  ctx.json(updated);
});
```

PUT replaces fields on an existing record — same id, new `title` and `done`. Missing id still throws
`NotFoundError`; bad body still throws `BadRequestError`.

```bash
curl -X PUT http://localhost:8080/tasks/1 \
  -H 'Content-Type: application/json' \
  -d '{"title":"Ship the tutorial","done":true}'
# → {"id":1,"title":"Ship the tutorial","done":true}
```

</details>

<details>
<summary>Solution — Advanced (repository)</summary>

Move the `Map` behind a factory so handlers talk to methods, not storage:

```ts twoslash title="src/task-repository.ts"
export type Task = { id: number; title: string; done: boolean };

export function createTaskRepository() {
  const tasks = new Map<number, Task>();
  let nextId = 1;

  return {
    create(title: string): Task {
      const task: Task = { id: nextId++, title, done: false };
      tasks.set(task.id, task);
      return task;
    },
    findById(id: number): Task | undefined {
      return tasks.get(id);
    },
    findAll(): Task[] {
      return [...tasks.values()];
    },
    delete(id: number): boolean {
      return tasks.delete(id);
    },
  };
}

const repo = createTaskRepository();
//    ^?
```

Handlers shrink to lookups and throws — no `Map` or `nextId` in the route file:

```ts title="src/index.ts (handlers use the repository)"
import { createTaskRepository } from './task-repository.js';

const tasks = createTaskRepository();

router.get('/tasks', (ctx) => {
  ctx.json(tasks.findAll());
});

router.post('/tasks', (ctx) => {
  const body = ctx.body as { title?: string };
  if (!body?.title) throw new BadRequestError('title is required');

  const task = tasks.create(body.title);
  ctx.status = 201;
  ctx.json(task);
});

router.get('/tasks/:id', (ctx) => {
  const task = tasks.findById(Number(ctx.params.id));
  if (!task) throw new NotFoundError('Task not found');
  ctx.json(task);
});
```

Same HTTP behavior — the repository is where you swap in-memory storage for a database later
without touching route handlers.

</details>

<details>
<summary>Solution — Expert (logger middleware)</summary>

Extract a small middleware function. Register `json()` **first**, then the logger, then routes:

```ts title="src/middleware/request-logger.ts"
import type { Context } from 'nextrush';

export function requestLogger() {
  return async (ctx: Context) => {
    console.log(`→ ${ctx.method} ${ctx.path}`);
    await ctx.next();
  };
}
```

```ts title="src/index.ts (middleware order)"
import { requestLogger } from './middleware/request-logger.js';

const app = createApp();
app.use(json()); // parse bodies before anything that reads ctx.body
app.use(requestLogger());

const router = createRouter();
// ... routes unchanged ...
```

Every request now prints `→ GET /tasks/1` (or similar) before the handler runs. Bodies still
parse because `json()` sits above the logger — not inside a handler, not after `app.route(...)`.

<Callout type="info">
  `createApp()`'s default logger is a no-op, so `console.log` is fine for this exercise. In
  production, swap in [`@nextrush/logger`](/docs/production/observability/logging) or pass
  `createApp({ logger: console })`.
</Callout>

</details>
