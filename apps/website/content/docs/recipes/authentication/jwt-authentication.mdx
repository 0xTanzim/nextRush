---
title: JWT Authentication (Functional)
description: Verify a bearer JWT in plain middleware — no class runtime required.
---

Not every app needs the guard/controller machinery. This recipe verifies a JWT on incoming
requests using functional middleware only — `jsonwebtoken` plus `ctx.get()`/`ctx.state`. JWT
signing and verification is not a NextRush package; `jsonwebtoken` is a third-party dependency
you install and manage like any other.

For guard-based auth with role checks and refresh tokens on class-based controllers, see the
[Authentication guide](/docs/guides/authentication/authentication) instead — this recipe is the minimal
functional equivalent of its verification step alone.

## Solution

```ts title="src/middleware/require-auth.ts"
import jwt from 'jsonwebtoken';
import { UnauthorizedError } from 'nextrush';
import type { Middleware } from 'nextrush';

const JWT_SECRET = process.env.JWT_SECRET;

if (!JWT_SECRET || JWT_SECRET.length < 32) {
  throw new Error('JWT_SECRET env variable must be set and at least 32 characters');
}

interface JwtPayload {
  sub: string;
  email: string;
}

export const requireAuth: Middleware = async (ctx) => {
  const header = ctx.get('authorization');

  if (!header || !header.startsWith('Bearer ')) {
    throw new UnauthorizedError('Missing bearer token');
  }

  const token = header.slice('Bearer '.length);

  try {
    const payload = jwt.verify(token, JWT_SECRET) as JwtPayload;
    ctx.state.user = { id: payload.sub, email: payload.email };
  } catch {
    throw new UnauthorizedError('Invalid or expired token');
  }

  await ctx.next();
};
```

```ts title="src/index.ts"
import { createApp, listen, errorHandler } from 'nextrush';
import { requireAuth } from './middleware/require-auth';

const app = createApp();

app.use(errorHandler());

app.get('/public', (ctx) => {
  ctx.json({ message: 'anyone can see this' });
});

app.get('/me', requireAuth, (ctx) => {
  ctx.json({ user: ctx.state.user });
});

listen(app, 8080);
```

`ctx.get('authorization')` is the case-insensitive header lookup — `ctx.headers` works too but
requires matching the exact casing the client sent. `ctx.state` is a per-request bag for sharing
data between middleware and handlers; storing the decoded payload there is what lets the route
handler read `ctx.state.user` without re-verifying the token. `requireAuth` calls `ctx.next()`
only after verification succeeds, so a rejected token never reaches the handler. See
[Context](/docs/concepts/context) and [Middleware](/docs/concepts/middleware) for both APIs.

<Callout type="warn" title="Route-level, not global">
  Register `requireAuth` per-route (or per-router with `app.route()`) rather than with a single
  global `app.use(requireAuth)` — a global registration would also block public routes like
  `/health` or `/public` above.
</Callout>

## Try It

```bash
# No token — rejected
curl -i http://localhost:8080/me

# With a token signed using the same JWT_SECRET
TOKEN=$(node -e "console.log(require('jsonwebtoken').sign({ sub: '1', email: 'a@example.com' }, process.env.JWT_SECRET))")
curl http://localhost:8080/me -H "Authorization: Bearer $TOKEN"
```

**Expected result:** the first call returns `401` with an `UnauthorizedError` body; the second
returns `{"user":{"id":"1","email":"a@example.com"}}`.
