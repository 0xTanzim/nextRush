Implement JWT authentication with guards — in both **class-based** (decorators + DI) and **functional** (plain routes) styles.

This example demonstrates:

- JWT token generation
- Guard-based protection
- Role-based access control
- Refresh token flow

<Callout type="error" title="Security Notice">
  Never hardcode credentials or JWT secrets. This example reads `JWT_SECRET` from environment
  variables — always do the same in production. Add rate limiting to authentication endpoints to
  prevent brute-force attacks.
</Callout>

---

## Why Argon2?

This guide uses **Argon2** (Argon2id variant) for password hashing — the current industry recommendation
for new applications.

| Criterion | Argon2 | bcrypt |
|-----------|--------|--------|
| GPU/ASIC resistance | Built-in memory-hard design | Limited by design era |
| Salt | Automatic, per-hash | Automatic, per-hash |
| Parameter tuning | Memory, time, parallelism | Cost factor only |
| Recommended for | **New projects** | Legacy compatibility |

Argon2 won the [Password Hashing Competition](https://www.password-hashing.net/) (PHC) in 2015 and is
the recommended choice in [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
The `argon2` npm package uses Argon2id by default — the safest variant against both GPU and side-channel
attacks.

<Callout type="warn" title="Legacy Note">
  Existing projects using `bcrypt` or `bcryptjs` remain secure today. A migration is not urgent —
  bcrypt is not broken. This guide recommends Argon2 for **new projects** and new user registrations.
  For migration guides and bcrypt interop, see the [Security Best Practices](/docs/guides/security/security)
  page.
</Callout>

## Auth Service

The auth service handles registration, login, token generation, and refresh workflows.

<details>
<summary>Complete AuthService implementation (click to expand)</summary>

```typescript title="src/services/auth.service.ts"
import { Service } from 'nextrush/class';
import { SignJWT, jwtVerify } from 'jose';
import argon2 from 'argon2';
import { UnauthorizedError, BadRequestError, ConflictError } from 'nextrush';
import type { User, JwtPayload, LoginDto, RegisterDto, TokenResponse } from '../types';

const JWT_SECRET = new TextEncoder().encode(
  process.env.JWT_SECRET ?? '',
);
const JWT_EXPIRES_IN = '15m';
const REFRESH_EXPIRES_IN = '7d';

if (JWT_SECRET.length < 32) {
  throw new Error('JWT_SECRET env variable must be at least 32 characters');
}

@Service()
export class AuthService {
  // In-memory user store (use database in production)
  private users: Map<string, User> = new Map();
  private refreshTokens: Set<string> = new Set();

  constructor() {
    // Seed admin user
    this.createUser('admin@example.com', 'admin123', 'admin');
  }

  private async createUser(
    email: string,
    password: string,
    role: 'user' | 'admin' = 'user'
  ): Promise<User> {
    const hashedPassword = await argon2.hash(password);
    const user: User = {
      id: Date.now().toString(),
      email,
      password: hashedPassword,
      role,
      createdAt: new Date().toISOString(),
    };
    this.users.set(user.id, user);
    return user;
  }

  async register(data: RegisterDto): Promise<TokenResponse> {
    // Validate
    if (!data.email || !data.password) {
      throw new BadRequestError('Email and password are required');
    }

    if (data.password.length < 6) {
      throw new BadRequestError('Password must be at least 6 characters');
    }

    // Check duplicate
    const existing = Array.from(this.users.values()).find((u) => u.email === data.email);
    if (existing) {
      throw new ConflictError('Email already registered');
    }

    // Create user
    const user = await this.createUser(data.email, data.password);

    // Generate tokens
    return this.generateTokens(user);
  }

  async login(data: LoginDto): Promise<TokenResponse> {
    // Validate
    if (!data.email || !data.password) {
      throw new BadRequestError('Email and password are required');
    }

    // Find user
    const user = Array.from(this.users.values()).find((u) => u.email === data.email);
    if (!user) {
      throw new UnauthorizedError('Invalid credentials');
    }

    // Verify password
    const isValid = await argon2.verify(user.password, data.password);
    if (!isValid) {
      throw new UnauthorizedError('Invalid credentials');
    }

    // Generate tokens
    return this.generateTokens(user);
  }

  async refresh(refreshToken: string): Promise<TokenResponse> {
    if (!refreshToken || !this.refreshTokens.has(refreshToken)) {
      throw new UnauthorizedError('Invalid refresh token');
    }

    try {
      const { payload } = await jwtVerify(refreshToken, JWT_SECRET);
      const user = this.users.get(payload.sub as string);

      if (!user) {
        throw new UnauthorizedError('User not found');
      }

      // Invalidate old refresh token
      this.refreshTokens.delete(refreshToken);

      // Generate new tokens
      return this.generateTokens(user);
    } catch {
      throw new UnauthorizedError('Invalid refresh token');
    }
  }

  async logout(refreshToken: string): Promise<void> {
    this.refreshTokens.delete(refreshToken);
  }

  async verifyToken(token: string): Promise<JwtPayload> {
    try {
      const { payload } = await jwtVerify(token, JWT_SECRET);
      return payload as unknown as JwtPayload;
    } catch {
      throw new UnauthorizedError('Invalid or expired token');
    }
  }

  getUserById(id: string): User | undefined {
    return this.users.get(id);
  }

  private generateTokens(user: User): TokenResponse {
    const claims = {
      sub: user.id,
      email: user.email,
      role: user.role,
    };

    const accessToken = new SignJWT(claims)
      .setProtectedHeader({ alg: 'HS256' })
      .setIssuedAt()
      .setExpirationTime(JWT_EXPIRES_IN)
      .sign(JWT_SECRET);

    const refreshToken = new SignJWT(claims)
      .setProtectedHeader({ alg: 'HS256' })
      .setIssuedAt()
      .setExpirationTime(REFRESH_EXPIRES_IN)
      .sign(JWT_SECRET);

    // Store refresh token
    this.refreshTokens.add(refreshToken);

    return {
      accessToken,
      refreshToken,
      expiresIn: 15 * 60, // 15 minutes in seconds
    };
  }
}
```

</details>

<Callout type="warn" title="In-Memory Store">
  `refreshTokens` and `users` are in-memory `Map`/`Set` instances for demonstration only. They
  reset on restart and are not shared across multiple server instances — use Redis or a
  database-backed store in production.
</Callout>

## Guards

```typescript title="src/guards/auth.guard.ts"
import type { GuardFn } from 'nextrush/class';
import { container } from 'nextrush/class';
import { AuthService } from '../services/auth.service';

export const AuthGuard: GuardFn = async (ctx) => {
  const authHeader = ctx.get('authorization');

  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    return false;
  }

  const token = authHeader.slice(7); // Remove 'Bearer '

  try {
    const authService = container.resolve(AuthService);
    const payload = await authService.verifyToken(token);

    // Store user info in state
    ctx.state.user = {
      id: payload.sub,
      email: payload.email,
      role: payload.role,
    };

    return true;
  } catch {
    return false;
  }
};
```

The role guard uses a factory pattern — it returns a guard function configured for the specified roles.

```typescript title="src/guards/role.guard.ts"
import type { GuardFn } from 'nextrush/class';

interface AuthUser {
  id: string;
  email: string;
  role: string;
}

export const RoleGuard =
  (allowedRoles: string[]): GuardFn =>
  async (ctx) => {
    const user = ctx.state.user as AuthUser | undefined;

    if (!user) {
      return false;
    }

    return allowedRoles.includes(user.role);
  };

// Convenience guard for admin-only routes
export const AdminGuard = RoleGuard(['admin']);
```

## Auth Controller

```typescript title="src/controllers/auth.controller.ts"
import { Controller, Post, Body, Ctx } from 'nextrush/class';
import type { Context } from 'nextrush';
import { AuthService } from '../services/auth.service';
import type { LoginDto, RegisterDto } from '../types';

@Controller('/auth')
export class AuthController {
  constructor(private authService: AuthService) {}

  @Post('/register')
  async register(@Body() data: RegisterDto, @Ctx() ctx: Context) {
    const tokens = await this.authService.register(data);
    ctx.status = 201;
    return tokens;
  }

  @Post('/login')
  async login(@Body() data: LoginDto) {
    return this.authService.login(data);
  }

  @Post('/refresh')
  async refresh(@Body() body: { refreshToken: string }) {
    return this.authService.refresh(body.refreshToken);
  }

  @Post('/logout')
  async logout(@Body() body: { refreshToken: string }, @Ctx() ctx: Context) {
    await this.authService.logout(body.refreshToken);
    ctx.status = 204;
  }
}
```

## Protected Controller

```typescript title="src/controllers/user.controller.ts"
import { Controller, Get, UseGuard, Ctx } from 'nextrush/class';
import type { Context } from 'nextrush';
import { AuthGuard } from '../guards/auth.guard';
import { AdminGuard } from '../guards/role.guard';

@UseGuard(AuthGuard) // All routes require authentication
@Controller('/users')
export class UserController {
  // GET /users/me - Current user profile
  @Get('/me')
  getProfile(@Ctx() ctx: Context) {
    const user = ctx.state.user as { id: string; email: string; role: string };
    return {
      id: user.id,
      email: user.email,
      role: user.role,
    };
  }

  // GET /users/admin - Admin only
  @UseGuard(AdminGuard)
  @Get('/admin')
  adminDashboard() {
    return {
      message: 'Welcome, admin!',
      stats: { users: 100, orders: 500 },
    };
  }
}
```

## Functional Approach

The class-based example above uses decorators (`@Service`, `@Controller`, `@UseGuard`) and
dependency injection. The same auth logic works without `nextrush/class` imports — plain routes,
manual middleware, no auto-discovery.

<Callout type="info" title="Same AuthService">
  The `AuthService` class from the class-based example uses `@Service()` for DI registration,
  but its constructor and methods are plain TypeScript — no decorator dependencies in the
  business logic. It works as-is in a functional setup:
  `export const authService = new AuthService();`
  The `@Service()` decorator is harmless without a DI container; skip it if you prefer.
</Callout>

### Route File

Routes and middleware live in a single file, wired by hand:

```typescript title="src/routes/auth.ts"
import { createRouter } from 'nextrush';
import { jwtVerify } from 'jose';
import { authService } from '../services/auth.service';
import type { LoginDto, RegisterDto } from '../types';

const JWT_SECRET = new TextEncoder().encode(process.env.JWT_SECRET ?? '');

// Middleware: Verify Bearer token
export const authMiddleware = async (ctx: any, next: any) => {
  const header = ctx.get('authorization');
  if (!header?.startsWith('Bearer ')) {
    ctx.status = 401;
    ctx.json({ error: 'Unauthorized' });
    return;
  }

  try {
    const { payload } = await jwtVerify(header.slice(7), JWT_SECRET);
    ctx.state.user = payload;
    await next();
  } catch {
    ctx.status = 401;
    ctx.json({ error: 'Invalid or expired token' });
  }
};

// Middleware: Role check (factory)
export const roleMiddleware = (...roles: string[]) =>
  async (ctx: any, next: any) => {
    const user = ctx.state.user as { role: string } | undefined;
    if (!user || !roles.includes(user.role)) {
      ctx.status = 403;
      ctx.json({ error: 'Forbidden' });
      return;
    }
    await next();
  };

export const authRouter = createRouter();

authRouter.post('/register', async (ctx) => {
  const result = await authService.register(ctx.body as RegisterDto);
  ctx.status = 201;
  ctx.json(result);
});

authRouter.post('/login', async (ctx) => {
  const result = await authService.login(ctx.body as LoginDto);
  ctx.json(result);
});

authRouter.post('/refresh', async (ctx) => {
  const { refreshToken } = ctx.body as { refreshToken: string };
  ctx.json(await authService.refresh(refreshToken));
});

authRouter.post('/logout', async (ctx) => {
  const { refreshToken } = ctx.body as { refreshToken: string };
  await authService.logout(refreshToken);
  ctx.status = 204;
});
```

### Entry Point

```typescript title="src/index.ts"
import { createApp, listen, errorHandler } from 'nextrush';
import { cors } from '@nextrush/cors';
import { json } from '@nextrush/body-parser';
import { authRouter, authMiddleware, roleMiddleware } from './routes/auth';

const app = createApp();

app.use(errorHandler());
app.use(cors());
app.use(json());

// Mount auth routes at /auth — no auto-discovery
app.route('/auth', authRouter);

// Protected routes with explicit middleware
app.get('/users/me', authMiddleware, async (ctx) => {
  const user = ctx.state.user as { sub: string; email: string; role: string };
  ctx.json({ id: user.sub, email: user.email, role: user.role });
});

app.get('/users/admin', authMiddleware, roleMiddleware('admin'), async (ctx) => {
  ctx.json({ message: 'Welcome, admin!', stats: { users: 100, orders: 500 } });
});

// 404
app.use((ctx) => {
  ctx.status = 404;
  ctx.json({ error: 'Not Found' });
});

await listen(app, 8080);
```

### When to Choose Each

| Aspect | Class-Based | Functional |
|--------|-------------|------------|
| Route registration | Auto-discovered via `registerControllers` | Manual `app.route()` / `app.get()` |
| Guard/middleware | Reusable guard objects via `@UseGuard` | Inline or exported middleware |
| AuthService wiring | DI container injects it | `new AuthService()` directly |
| Dependencies | `nextrush/class` + decorator transpiler | No extra imports |
| Best for | Larger apps, multiple controllers | Small APIs, quick prototypes |

Pick class-based for structure and auto-discovery as your app grows. Pick functional when you
want minimal setup and full control over the wiring.

## Security Considerations

This example uses in-memory storage for users and refresh tokens, as noted above. In production,
replace both with a database and a Redis-backed store using TTL-based expiration.

### Password Hashing Rules

- **Never encrypt passwords** — hashing is one-way by design. Encryption implies decryption, which is
  never needed for authentication.
- **Always hash passwords** — never store or transmit plaintext passwords.
- **Each password gets a unique salt** — Argon2 handles this automatically per-hash. No manual salt
  management needed.
- **Use library defaults** — `argon2.hash()` uses memory=64MB, time=3, parallelism=4 by default.
  Tune only if you have specific hardware or compliance requirements.
- **Never set your own salt** — trust the library to generate a cryptographically random salt per hash.

### Production Checklist

- **Store users in a database**, not memory
- **Use Redis** for refresh tokens with TTL
- **Add rate limiting** to auth endpoints
- **Use HTTPS** in production
- **Validate email format** before registration
- **Add account lockout** after repeated failed attempts
