<DocHero eyebrow="Framework overview">

NextRush is a small, composable HTTP stack. Each request gets a single `Context` object, and you
wrap Koa-style middleware around a fast router. Controllers and DI are there when an app grows into
needing them, not before. The core has zero runtime dependencies. You pull in `@nextrush/*`
middleware and plugins only when a real need shows up, and the same application code runs on Node.js,
Bun, Deno, and Edge.

</DocHero>

<Callout type="info" title="How to read this section">
  **NextRush v3 (current line: 3.0.x)** — semver patch releases; public APIs follow semver for breaking changes.
  Requires **Node.js 22+**. For positioning vs other stacks and a short mental model, read [Introduction](/docs/getting-started)
  first; this page is the full stack map.
</Callout>

## Hello World in under a minute

<PackageInstall packages={['nextrush']} />

```typescript title="src/index.ts"
import { createApp, createRouter, listen } from 'nextrush';

const app = createApp();
const router = createRouter();

router.get('/', (ctx) => ctx.json({ message: 'Hello NextRush' }));

app.route('/', router);
await listen(app, 8080);
// → http://localhost:8080
```

## How a request flows

Every HTTP request follows the same path:

<Mermaid
  chart={`
sequenceDiagram
    participant Client
    participant Adapter
    participant App as Application
    participant MW as Middleware
    participant Router
    participant Handler

    Client->>Adapter: HTTP Request
    Adapter->>App: Create Context
    App->>MW: Run middleware pipeline
    MW->>MW: cors → auth → body-parser
    MW->>Router: Match route
    Router->>Handler: Execute handler
    Handler-->>MW: Return response
    MW-->>MW: Post-processing (logging, headers)
    MW-->>Adapter: Final response
    Adapter-->>Client: HTTP Response

`}
/>

1. **Adapter** receives the raw request and builds a **Context**
2. **Application** runs the **middleware** pipeline
3. **Router** matches the URL and extracts params
4. **Handler** runs your logic and sets the response
5. Response unwinds through middleware
6. **Adapter** sends bytes to the client

## Core concepts

Eight ideas cover most of the framework. Each has a dedicated concept page.

### Application

The container for middleware, plugins, routes, and errors.

```typescript
import { createApp } from 'nextrush';

const app = createApp();
```

[Application →](/docs/concepts/application)

### Context

One object per request for input, output, and shared state.

```typescript
router.get('/users/:id', (ctx) => {
  const { id } = ctx.params;
  const { page } = ctx.query;
  const auth = ctx.get('authorization');

  ctx.status = 200;
  ctx.json({ id, page, auth });
});
```

[Context →](/docs/concepts/context)

### Middleware

Onion-style pipeline — code before `ctx.next()` runs inbound; code after runs outbound.

```typescript
app.use(async (ctx) => {
  const start = Date.now();
  await ctx.next();
  ctx.set('X-Response-Time', `${Date.now() - start}ms`);
});
```

<Mermaid
  chart={`
flowchart LR
    subgraph "Middleware pipeline"
        direction LR
        A["Request →"] --> B["cors"]
        B --> C["auth"]
        C --> D["body-parser"]
        D --> E["Router + handler"]
        E --> F["← body-parser"]
        F --> G["← auth"]
        G --> H["← cors"]
        H --> I["← Response"]
    end
`}
/>

[Middleware →](/docs/concepts/middleware)

### Routing

Segment trie with O(k) lookup, where k is the number of path segments; static routes use fast paths. Params, wildcards, and nested routers supported.

```typescript
import { createRouter } from 'nextrush';

const users = createRouter();

users.get('/', (ctx) => ctx.json([]));
users.get('/:id', (ctx) => ctx.json({ id: ctx.params.id }));
users.post('/', (ctx) => {
  ctx.status = 201;
  ctx.json(ctx.body);
});

app.route('/users', users);
```

[Routing →](/docs/concepts/routing)

### Extensions, middleware, and registrars

Extend the app at startup. Most extension work is **middleware** (`app.use`); a plain **registrar**
function covers wiring that already holds the object it configures (like controllers); the
**Extension** kind (`app.extend()` + `app.ready()`) is rare — reserved for long-lived services that
attach state to the app, like an event bus.

```typescript
import { events } from '@nextrush/events';
import { registerControllers } from 'nextrush/class';

app.extend(events());
await app.ready();
app.events.emit('server:started', {});

await registerControllers(app, { root: './src' });
```

[Extensions →](/docs/concepts/plugins)

### Guards

Route-level access checks. Return `false` → 403 before the handler runs.

```typescript
import { UseGuard, Controller, Get, type GuardFn } from 'nextrush/class';

const AuthGuard: GuardFn = (ctx) => {
  return Boolean(ctx.get('authorization'));
};

@UseGuard(AuthGuard)
@Controller('/admin')
export class AdminController {
  @Get('/dashboard')
  dashboard() {
    return { admin: true };
  }
}
```

[Guards →](/docs/concepts/guards)

### Dependency injection

Register services (singleton or transient) and inject into controllers.

```typescript
import { Service, Controller, Get } from 'nextrush/class';

@Service()
export class UserService {
  async findAll() {
    return [{ id: 1, name: 'Alice' }];
  }
}

@Controller('/users')
export class UserController {
  constructor(private users: UserService) {}

  @Get()
  findAll() {
    return this.users.findAll();
  }
}
```

[Dependency injection →](/docs/concepts/di-decorators)

### Adapters

Runtime-specific HTTP I/O. Your app code stays the same.

```typescript
import { listen } from 'nextrush'; // Node.js (default)
// import { listen } from '@nextrush/adapter-bun';   // Bun
// import { listen } from '@nextrush/adapter-deno';   // Deno

await listen(app, 8080); // Node, Bun, Deno

// Edge (Cloudflare, Vercel) has no listen() — export a fetch handler instead:
// import { createFetchHandler } from '@nextrush/adapter-edge';
// export default { fetch: createFetchHandler(app) };
```

[Adapters →](/docs/concepts/runtime-compatibility)

## Beyond routing

A real API needs more than routes. These ship as separate packages, so the core stays small — add them as the need shows up:

- **Validation** — `@nextrush/validation` runs any Standard Schema validator (Zod, Valibot, ArkType) as `validate()` middleware.
- **API docs** — `@nextrush/openapi` reads your route metadata and `validate()` schemas to generate an OpenAPI 3.1 document and docs UI, with zero config.
- **Streaming** — `@nextrush/stream` writes text, Server-Sent Events (SSE), and NDJSON responses, built for AI and agentic apps.
- **Real-time** — `@nextrush/websocket` adds WebSocket connections alongside your HTTP routes.
- **File uploads** — `@nextrush/multipart` parses multipart form-data.

`validation`, `openapi`, and `stream` are the newest packages and are rolling out to npm. For everything published today, see [the package finder](/docs/api-reference#which-package-do-i-need).

## Two programming styles

Use functions for small services; add controllers and DI when the API grows. Both styles can coexist.

<Tabs items={['Functional', 'Class-based']}>
  <Tab value="Functional">
    Direct routes and middleware.

    ```typescript title="src/index.ts"
    import { createApp, createRouter, listen } from 'nextrush';
    import { cors } from '@nextrush/cors';
    import { json } from '@nextrush/body-parser';

    const app = createApp();
    const router = createRouter();

    app.use(cors());
    app.use(json());

    router.get('/users', (ctx) => {
      ctx.json([{ id: 1, name: 'Alice' }]);
    });

    router.post('/users', (ctx) => {
      ctx.status = 201;
      ctx.json(ctx.body);
    });

    router.get('/users/:id', (ctx) => {
      ctx.json({ id: ctx.params.id });
    });

    app.route('/api', router);
    await listen(app, 8080);
    ```

  </Tab>
  <Tab value="Class-based">
    Controllers with DI. `registerControllers` only registers **exported** `@Controller` classes it finds under `root` (the scaffolder puts each in its own file under `src/`).

    ```typescript title="src/index.ts"
    import { createApp, listen } from 'nextrush';
    import { registerControllers, Controller, Get, Post, Body, Service } from 'nextrush/class';

    @Service()
    export class UserService {
      private users = [{ id: 1, name: 'Alice' }];

      findAll() {
        return this.users;
      }

      create(data: { name: string }) {
        const user = { id: this.users.length + 1, ...data };
        this.users.push(user);
        return user;
      }
    }

    @Controller('/users')
    export class UserController {
      constructor(private userService: UserService) {}

      @Get()
      findAll() {
        return this.userService.findAll();
      }

      @Post()
      create(@Body() data: { name: string }) {
        return this.userService.create(data);
      }
    }

    const app = createApp();

    await registerControllers(app, { root: './src', prefix: '/api' });

    await listen(app, 8080);
    ```

    The `nextrush` meta-package loads `reflect-metadata` for decorators.

  </Tab>
</Tabs>

<Callout type="info" title="Mix and match">
  Use functional routes for health checks and class controllers for domain APIs in the same app — no forced migration path.
</Callout>

## Design constraints

<DocTableWrap>

| Area | Constraint |
| --- | --- |
| Throughput | No universal RPS figure — use [Benchmarks](/docs/performance) on your CPU, Node version, and tooling |
| Core lines of code | &lt; 3,000 |
| Runtime dependencies | 0 in core; `reflect-metadata` for DI via the meta-package |

</DocTableWrap>

Segment trie routing, pre-compiled middleware composition, and avoiding extra allocations on the request path keep overhead low. Cold-start and idle memory depend on process and OS — measure in your environment if those drive your product.

[Full benchmarks →](/docs/performance)

## Coming from another stack?

<DocTableWrap>

| Topic | Express | Fastify | NextRush |
| --- | --- | --- | --- |
| **Request surface** | `req` / `res` / `next` | `request` / `reply` | Single **`ctx`** + **`ctx.next()`** (Koa-style) |
| **Routing** | Linear match order | Radix tree (`find-my-way`) | Segment trie (`@nextrush/router`) |
| **Types** | DefinitelyTyped | First-class | Strict, first-party types |
| **Validation** | Manual / middleware | JSON Schema (built-in) | Bring your own (Zod, Valibot, …) via param transforms |
| **Structure** | Free-form | Encapsulated plugins | Optional **controllers + DI** via `nextrush/class` |

</DocTableWrap>

### Express

- **Middleware**: `(req, res, next)` vs one **`ctx`** and `ctx.next()`
- **Routing**: linear scan vs segment trie (O(k) by path segments)
- **Types**: `@types/express` vs first-party strict types

### Fastify

- **Extensibility**: Fastify plugin encapsulation vs NextRush's three-kind model — middleware for the request pipeline, plain registrar functions for wiring, `app.extend()` for the rare long-lived service
- **Validation**: JSON Schema vs transforms (Zod, Valibot, …)
- **Decorators**: add-on only vs `@Controller` / `@Get` with DI when you want them

## What ships in `nextrush`

| Package                  | Role                                      |
| ------------------------ | ----------------------------------------- |
| `@nextrush/core`         | Application, middleware engine            |
| `@nextrush/router`       | Segment trie router                       |
| `@nextrush/adapter-node` | Node HTTP server                          |
| `@nextrush/errors`       | HTTP errors (4xx / 5xx)                   |
| `@nextrush/types`        | Shared types                              |

The `nextrush/class` entry additionally bundles `@nextrush/di`, `@nextrush/decorators`, and `@nextrush/controllers` (plus `reflect-metadata`).

Optional layers:

| Category       | Examples                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------- |
| **Middleware** | `cors`, `helmet`, `body-parser`, `compression`, `cookies`, `csrf`, `multipart`, `rate-limit`, `request-id`, `timer`, `validation` |
| **Extensions** | `controllers`, `events`, `logger`, `openapi`, `static`, `template`, `websocket`                            |
| **Streaming**  | `stream` (text, SSE, NDJSON — built for AI and agentic apps) |
| **Adapters**   | `adapter-bun`, `adapter-deno`, `adapter-edge`                                                   |
| **DI**         | `di`, `decorators`                                                                              |
