---
title: Build a Task API
description: A guided tutorial — build a real Task API with NextRush, from an empty folder to create, read, update, and delete over HTTP.
---

You'll build one thing here: a **Task API** you can actually talk to. By the end it stores tasks,
reads them back, updates them, and returns a real `404` when you ask for one that isn't there. No
copy-paste-and-hope — every step runs, and each builds on the last.

This is the manual path. You wire the server yourself so the router, the store, and middleware order
stay visible. Want a project generated for you instead? Use [create-nextrush](/docs/start/create-nextrush).

## What you'll build

A few endpoints backed by a real in-memory store. The finished API answers like this:

```bash
# create a task
curl -X POST http://localhost:8080/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Write the docs"}'
# → {"id":1,"title":"Write the docs","done":false}

# read that exact task back
curl http://localhost:8080/tasks/1
# → {"id":1,"title":"Write the docs","done":false}

# ask for one that doesn't exist
curl -i http://localhost:8080/tasks/999
# → HTTP/1.1 404 Not Found
```

That `999` returning a real 404 — not a hardcoded record — is the whole point. The `GET` gives back
what the `POST` stored, because there's an actual store underneath.

<Callout type="info" title="Prerequisites">
  **Node.js 22+** and a package manager. The commands use **pnpm**; npm and yarn work the same way.
  Basic TypeScript is assumed — no prior NextRush knowledge.
</Callout>

<Steps>

<Step>
### Create the project

```bash
mkdir task-api && cd task-api
pnpm init
```

Add `"type": "module"` to `package.json` so Node runs the TypeScript entry as ESM.

</Step>

<Step>
### Install NextRush

<PackageInstall packages={["nextrush", "@nextrush/body-parser"]} dev={["tsx", "typescript", "@types/node"]} />

`nextrush` is the framework. `@nextrush/body-parser` is separate on purpose — you only pay for JSON
parsing on the routes that need it, and you'll add it in step 5 exactly when the first `POST` needs a
parsed body. `tsx` runs TypeScript directly, no build step.

</Step>

<Step>
### Start a server with one route

Create `src/index.ts`:

```typescript title="src/index.ts"
import { createApp, createRouter, listen } from 'nextrush';

const app = createApp();
const router = createRouter();

router.get('/', (ctx) => {
  ctx.json({ name: 'Task API', status: 'ok' });
});

app.route('/', router);
await listen(app, 8080);
```

Run it:

```bash
npx tsx src/index.ts
```

The server stays up. NextRush's default logger is a no-op, so nothing prints — that's expected.
In another terminal:

```bash
curl http://localhost:8080/
# → {"name":"Task API","status":"ok"}
```

</Step>

<Step>
### Add a store and create tasks

Now the real work. Add an in-memory `Map` as the store, a `POST /tasks` that creates, and a
`GET /tasks` that lists what's there. A `Map` is enough for a tutorial — swap it for a database later
without changing the route shape.

```typescript title="src/index.ts"
import { createApp, createRouter, listen, BadRequestError } from 'nextrush';

type Task = { id: number; title: string; done: boolean };

const tasks = new Map<number, Task>();
let nextId = 1;

const app = createApp();
const router = createRouter();

router.get('/tasks', (ctx) => {
  ctx.json([...tasks.values()]);
});

router.post('/tasks', (ctx) => {
  const body = ctx.body as { title?: string };
  if (!body?.title) throw new BadRequestError('title is required');

  const task: Task = { id: nextId++, title: body.title, done: false };
  tasks.set(task.id, task);

  ctx.status = 201;
  ctx.json(task);
});

app.route('/', router);
await listen(app, 8080);
```

`ctx.body` is `undefined` for now — the server never parses the request body until you add the parser
in step 5. That's the next thing you'll fix, and you'll see exactly why.

</Step>

<Step>
### Parse the body, then read tasks back

The `POST` above reads `ctx.body`, but nothing populates it yet. Register the JSON body parser with
`app.use(json())` **before** the routes, so the body is parsed before a handler runs. Then add
`GET /tasks/:id`, which reads a task back out of the store — and throws `NotFoundError` when the id
isn't there.

```typescript title="src/index.ts"
import { createApp, createRouter, listen, BadRequestError, NotFoundError } from 'nextrush';
import { json } from '@nextrush/body-parser';

type Task = { id: number; title: string; done: boolean };

const tasks = new Map<number, Task>();
let nextId = 1;

const app = createApp();

// Parse JSON bodies before any route runs — without this, ctx.body stays undefined.
app.use(json());

const router = createRouter();

router.get('/tasks', (ctx) => {
  ctx.json([...tasks.values()]);
});

router.post('/tasks', (ctx) => {
  const body = ctx.body as { title?: string };
  if (!body?.title) throw new BadRequestError('title is required');

  const task: Task = { id: nextId++, title: body.title, done: false };
  tasks.set(task.id, task);

  ctx.status = 201;
  ctx.json(task);
});

router.get('/tasks/:id', (ctx) => {
  const task = tasks.get(Number(ctx.params.id));
  if (!task) throw new NotFoundError('Task not found');
  ctx.json(task);
});

app.route('/', router);
await listen(app, 8080);
```

Restart the server, then create a task and read it straight back:

```bash
curl -X POST http://localhost:8080/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Write the docs"}'
# → {"id":1,"title":"Write the docs","done":false}

curl http://localhost:8080/tasks/1
# → {"id":1,"title":"Write the docs","done":false}

curl -i http://localhost:8080/tasks/999
# → HTTP/1.1 404 Not Found  (NotFoundError became the response)
```

The `id:1` you get back is the one you stored, and `999` takes the real miss path. Throwing
`NotFoundError` is all it takes — NextRush's error handler turns any `HttpError` into the matching
status and JSON.

</Step>

<Step>
### Update and delete

Finish the CRUD set. `PATCH /tasks/:id` toggles `done`; `DELETE /tasks/:id` removes a task and
answers `204 No Content`. Add both to the router:

```typescript title="src/index.ts"
router.patch('/tasks/:id', (ctx) => {
  const task = tasks.get(Number(ctx.params.id));
  if (!task) throw new NotFoundError('Task not found');

  task.done = !task.done;
  ctx.json(task);
});

router.delete('/tasks/:id', (ctx) => {
  const existed = tasks.delete(Number(ctx.params.id));
  if (!existed) throw new NotFoundError('Task not found');

  ctx.status = 204;
  ctx.send('');
});
```

</Step>

</Steps>

## Verify it works

Restart, then run the whole flow — create, list, toggle, delete, confirm it's gone:

```bash
curl -X POST http://localhost:8080/tasks -H 'Content-Type: application/json' -d '{"title":"Ship it"}'
# → {"id":1,"title":"Ship it","done":false}

curl -X PATCH http://localhost:8080/tasks/1
# → {"id":1,"title":"Ship it","done":true}

curl http://localhost:8080/tasks
# → [{"id":1,"title":"Ship it","done":true}]

curl -X DELETE http://localhost:8080/tasks/1   # → 204, empty body
curl -i http://localhost:8080/tasks/1
# → HTTP/1.1 404 Not Found
```

The task you created is the task you toggled, listed, and then deleted. That round trip through a real
store is what a first API should teach.

## Complete code

<details>
<summary>Full <code>src/index.ts</code> — the finished Task API</summary>

```typescript title="src/index.ts"
import { createApp, createRouter, listen, BadRequestError, NotFoundError } from 'nextrush';
import { json } from '@nextrush/body-parser';

type Task = { id: number; title: string; done: boolean };

const tasks = new Map<number, Task>();
let nextId = 1;

const app = createApp();
app.use(json());

const router = createRouter();

router.get('/tasks', (ctx) => {
  ctx.json([...tasks.values()]);
});

router.post('/tasks', (ctx) => {
  const body = ctx.body as { title?: string };
  if (!body?.title) throw new BadRequestError('title is required');

  const task: Task = { id: nextId++, title: body.title, done: false };
  tasks.set(task.id, task);

  ctx.status = 201;
  ctx.json(task);
});

router.get('/tasks/:id', (ctx) => {
  const task = tasks.get(Number(ctx.params.id));
  if (!task) throw new NotFoundError('Task not found');
  ctx.json(task);
});

router.patch('/tasks/:id', (ctx) => {
  const task = tasks.get(Number(ctx.params.id));
  if (!task) throw new NotFoundError('Task not found');

  task.done = !task.done;
  ctx.json(task);
});

router.delete('/tasks/:id', (ctx) => {
  const existed = tasks.delete(Number(ctx.params.id));
  if (!existed) throw new NotFoundError('Task not found');

  ctx.status = 204;
  ctx.send('');
});

app.route('/', router);
await listen(app, 8080);
```

## What you learned

- **Routing** — `createRouter()`, path params like `/tasks/:id`, and mounting with `app.route()`. [Routing deep dive](/docs/concepts/routing)
- **Context** — reading `ctx.body`/`ctx.params` and writing with `ctx.json()` and `ctx.status`. [Context deep dive](/docs/concepts/context)
- **Middleware order** — `json()` runs before routes, or `ctx.body` stays `undefined`. [Middleware deep dive](/docs/concepts/middleware)
- **Errors** — throwing `NotFoundError`/`BadRequestError` and letting the framework map them to responses. [Error handling](/docs/guides/error-handling)
