Installing a web framework should take one command and a couple of minutes, not a checklist of
peripheral tooling. NextRush ships as a single meta-package with everything the functional core
needs, so the fastest path from an empty folder to a running server is genuinely short — you'll
have one here before this page ends.

## What you'll have

By the end of this page:

- ✓ NextRush installed with your package manager of choice
- ✓ Confirmation that your Node.js version meets the framework's requirement
- ✓ A one-file server running and answering a request on `localhost:8080`

## Prerequisites

- **Node.js 22.0.0 or newer.** [Download](https://nodejs.org/) or manage versions with
  [nvm](https://github.com/nvm-sh/nvm). NextRush declares `"engines": { "node": ">=22.0.0" }` in
  every published package — this isn't a recommendation, it's what the framework is built and
  tested against.
- **A package manager** — pnpm, npm, yarn, or bun. Examples on this page show all four.

<Callout type="info" title="Why Node.js 22?">
  The framework targets ES2022 and stable ESM throughout — no CommonJS build exists for any
  `@nextrush/*` package. Node 22 is the oldest LTS line where that target lands cleanly, so it's
  the floor every adapter and example assumes. See the [FAQ](/docs/resources/faq) for the full
  reasoning.
</Callout>

## Recommended approach

Two paths reach a running server. **Use the scaffolder if you want a project generated for
you** — it wires routing, middleware, scripts, and your chosen style (functional, class-based, or
full) in one command, and it's what the [Task API tutorial](/docs/start/quick-start) assumes you
skip if you're following this page instead. **Install by hand if you want to see every piece land**
— useful when you're adding NextRush to an existing project, or you want to understand the
manual setup before letting a generator do it for you.

Both install the same `nextrush` package underneath; the scaffolder automates the folder, config,
and file structure around it. If you're unsure, scaffold — you can still read every file it
produces afterward.

## Install manually

<Steps>

<Step>

### Create a project folder

```bash
mkdir my-api && cd my-api
pnpm init
```

Add `"type": "module"` to the generated `package.json`. NextRush is ESM-only — there's no
CommonJS build to fall back to — so Node needs to know your `.ts`/`.js` files are ES modules
before anything else runs.

</Step>

<Step>

### Install NextRush

<PackageInstall packages={['nextrush']} dev={['@nextrush/dev', 'tsx', 'typescript', '@types/node']} />

`nextrush` is the meta-package: it re-exports `@nextrush/core`, `@nextrush/router`,
`@nextrush/adapter-node`, `@nextrush/errors`, and `@nextrush/types`, so this one install covers
the functional path (`createApp`, `createRouter`, `listen`) with no separate package to add. Add
`@nextrush/dev` as a dev dependency so your project scripts can run `nextrush dev` and
`nextrush build`.

</Step>

<Step>

### Write a server and run it

Create `src/index.ts`:

```ts title="src/index.ts"
import { createApp, createRouter, listen } from 'nextrush';

const app = createApp();
const router = createRouter();

router.get('/', (ctx) => {
  ctx.json({ status: 'ok', framework: 'NextRush' });
});

app.route('/', router);
await listen(app, 8080);
```

Run it with `tsx` so there's no separate compile step while you're getting started:

```bash
npx tsx src/index.ts
```

**Expected output:** open `http://localhost:8080` (or `curl` it) and you should see:

```json
{ "status": "ok", "framework": "NextRush" }
```

If you see that response, NextRush is installed and serving requests. `createApp()` builds the
application, `createRouter()` gives you a router to attach routes to, `app.route('/', router)`
mounts it, and `listen(app, 8080)` starts the Node adapter.

</Step>

<Step>

### Configure TypeScript

NextRush ships full type definitions. This `tsconfig.json` matches what the framework's own
examples and CI run against:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "outDir": "dist",
    "rootDir": "src"
  },
  "include": ["src"]
}
```

<Callout type="info" title="Only using class-based controllers?">
  Add `"experimentalDecorators": true` and `"emitDecoratorMetadata": true` to
  `compilerOptions` if you import from `nextrush/class`. That entry point auto-imports
  `reflect-metadata` itself — you don't add it to your own code or dependencies.
</Callout>

</Step>

</Steps>

## Verify the install

Confirm the two things that actually matter before you build on top of this: the runtime version,
and that the server responds.

```bash
node --version
# → v22.x.x or newer — NextRush's package.json declares "engines": { "node": ">=22.0.0" }
```

```bash
curl http://localhost:8080/
# → {"status":"ok","framework":"NextRush"}
```

If `node --version` reports below 22, install a newer version before continuing — NextRush's
adapters and examples aren't tested against older lines, and package installs may warn or fail
depending on your package manager's `engines` enforcement.

## Production considerations

- **Pin your Node version in deployment.** `engines` in `package.json` documents the requirement;
  it doesn't enforce it everywhere a build might run (some platforms ignore it). Set the runtime
  version explicitly in your platform config or Dockerfile.
- **Install `@nextrush/dev` as a dev dependency only.** It's a build/CLI tool, not something your
  running server needs — keeping it out of `dependencies` keeps your production install smaller.
- **Beyond Node:** Bun and Deno need their matching adapter package instead of (or alongside)
  `@nextrush/adapter-node` — see the [Node runtime guide](/docs/start/runtime/node) and its
  siblings for per-runtime setup, including edge and serverless targets.

## Common mistakes

- **Server won't start; import errors on `nextrush`.** *Cause:* `package.json` is missing
  `"type": "module"`, so Node tries to load ESM output as CommonJS. *Fix:* add `"type": "module"`
  — NextRush publishes no CommonJS build for any package to fall back to.
- **`node --version` is below 22.** *Cause:* an older Node install or version manager default.
  *Fix:* install/select Node 22 or newer before running `pnpm add nextrush` — the framework's
  `engines` field expects it everywhere.
- **Decorators throw `reflect-metadata` errors.** *Cause:* importing `nextrush/class` without
  `experimentalDecorators`/`emitDecoratorMetadata` enabled in `tsconfig.json`. *Fix:* add both
  compiler options — the `reflect-metadata` import itself is already handled for you.
