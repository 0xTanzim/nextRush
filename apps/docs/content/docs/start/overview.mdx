---
title: What Is NextRush?
description: A Node.js HTTP framework with a zero-dependency functional core and an optional class-based runtime, covered before you write your first route.
---

NextRush is an HTTP framework for Node.js built around one per-request `Context` object and a
Koa-style middleware pipeline. Routes are matched by a segment trie, so lookup cost depends on how
many segments a URL has, not on how many routes you've registered. You install the framework core,
then add a package for each capability you need — validation, security headers, dependency
injection — instead of taking on a fixed bundle.

## Two ways to write a route

NextRush gives you two styles for the same request pipeline, and you can mix them in one project.

**Functional** — `createApp()` and `createRouter()`, plain handler functions:

```ts
import { createApp, createRouter, listen } from 'nextrush';

const app = createApp();
const router = createRouter();

router.get('/users/:id', (ctx) => ctx.json({ id: ctx.params.id }));

app.route('/', router);
await listen(app, 8080);
```

**Class-based** — `@Controller` classes with dependency injection, from `nextrush/class`:

```ts
import { Controller, Get, Param } from 'nextrush/class';

@Controller('/users')
class UserController {
  @Get('/:id')
  findOne(@Param('id') id: string) {
    return { id };
  }
}
```

Both compile to the same routing and middleware underneath — there's no functional-vs-class
performance trade-off, only a style choice. [Application](/docs/concepts/application) covers the
functional path in depth; [dependency injection](/docs/concepts/dependency-injection) covers the
class-based one.

## What's zero-dependency, and what isn't

"Zero dependencies" isn't true for the whole framework — it depends on which path you import.
`createApp`, `createRouter`, and `listen` come from `@nextrush/core`, `@nextrush/router`, and
`@nextrush/adapter-node`. Checked directly against `packages/core/package.json`: its only
`dependencies` are the internal `@nextrush/errors` and `@nextrush/types` workspace packages — no
external runtime package. `@nextrush/router`'s only dependency is the same internal
`@nextrush/types`.

`nextrush/class` is a different story: `packages/di/package.json` lists `reflect-metadata` and
`tsyringe` as real runtime dependencies — the DI container decorators are built on. Import
`nextrush/class` and those two packages come with it; stay on the functional path and they don't.

## What you can build

- REST APIs and internal services, either style
- Class-based applications with guards, interceptors, and request-scoped dependencies
- Streaming responses — SSE and NDJSON — for AI/agentic apps
- Services that share the same application code across Node.js, Bun, Deno, and the edge
