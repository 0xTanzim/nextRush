minimal example, and a link to the full page. Read top to bottom once, then use the deep-dive
links as your reference map.

## What NextRush is

NextRush is a Node.js HTTP framework built around a single per-request `Context` object and a
Koa-style middleware pipeline. The core has zero runtime dependencies, routes through a segment
trie, and stays under 3,000 lines of code. Everything past routing and middleware — validation,
security headers, DI, controllers — is a separate package you add when you need it.

## Application

`createApp()` builds the orchestrator: it holds your middleware stack, boots any extensions, and
produces the request handler an adapter serves.

```typescript
import { createApp, listen } from 'nextrush';

const app = createApp();
await listen(app, 8080);
```

[Application → deep dive](/docs/concepts/application)

## Context

Every request gets one `ctx` object — your interface for reading the request and writing the
response. There's no shared state across requests unless you put it there yourself.

```typescript
router.get('/users/:id', (ctx) => {
  const { id } = ctx.params;
  ctx.status = 200;
  ctx.json({ id });
});
```

[Context → deep dive](/docs/concepts/context)

## Routing

Routes are matched by a segment trie — lookup cost depends on the number of path segments in the
URL, not on how many routes you've registered. Static segments, params, and wildcards are all
supported.

```typescript
import { createRouter } from 'nextrush';

const users = createRouter();
users.get('/', (ctx) => ctx.json([]));
users.get('/:id', (ctx) => ctx.json({ id: ctx.params.id }));

app.route('/users', users);
```

[Routing → deep dive](/docs/concepts/routing)

## Middleware

Middleware wraps the request in an onion. Code before `ctx.next()` runs on the way in; code after
runs on the way out — in reverse registration order.

```typescript
app.use(async (ctx) => {
  const start = Date.now();
  await ctx.next();
  ctx.set('X-Response-Time', `${Date.now() - start}ms`);
});
```

[Middleware → deep dive](/docs/concepts/middleware)

## Error handling

Thrown `HttpError` subclasses map to a status code and a consistent JSON shape. Throw from any
middleware or handler — the application's error handler catches it centrally.

```typescript
import { NotFoundError } from 'nextrush';

router.get('/users/:id', async (ctx) => {
  const user = await db.findUser(ctx.params.id);
  if (!user) throw new NotFoundError('User not found');
  ctx.json(user);
});
```

## Extending NextRush

Capability is added through three idioms, unequal in weight. Reach for middleware first — it
covers almost everything.

```typescript
// Middleware (~99%) — the default
app.use(cors());

// Registrar (~0.9%) — wires a subsystem with a direct call
await registerControllers(app, { root: './src' });

// Extension (~0.1%, rare) — long-lived, app-scoped service
app.extend(events());
await app.ready();
```

[Extending → deep dive](/docs/concepts/extensions)

## Dependency injection & scopes

`nextrush/class` wraps tsyringe to resolve constructor dependencies from TypeScript's emitted
parameter types. Services are singleton by default; `transient` gives a fresh instance per
resolve, `request` shares one instance across a single HTTP request.

```typescript
import { Service } from 'nextrush/class';

@Service() // singleton by default
class UserService {
  findAll() {
    return [{ id: 1, name: 'Alice' }];
  }
}
```

[Dependency injection & scopes → deep dive](/docs/concepts/dependency-injection)

## Modules

A `@Module` groups a feature's controllers and providers behind one declaration. Modules compose
other modules through `imports`, and `registerModule()` reuses the same registration pipeline as
`registerControllers()`.

```typescript
import { Module, Controller, Get, Service, registerModule } from 'nextrush/class';

@Service()
class UserService {
  findAll() {
    return [{ id: 1, name: 'Alice' }];
  }
}

@Controller('/users')
class UserController {
  constructor(private users: UserService) {}
  @Get() findAll() { return this.users.findAll(); }
}

@Module({ controllers: [UserController], providers: [UserService] })
class UserModule {}

await registerModule(app, UserModule);
```

[Modules → deep dive](/docs/concepts/modules)

## Guards

Guards are declarative access control for controller-based routes — a boolean gatekeeper that
runs before the handler.

```typescript
import { UseGuard, Controller, Get, type GuardFn } from 'nextrush/class';

const AuthGuard: GuardFn = (ctx) => Boolean(ctx.get('authorization'));

@UseGuard(AuthGuard)
@Controller('/admin')
class AdminController {
  @Get('/dashboard')
  dashboard() {
    return { admin: true };
  }
}
```

[Guards → deep dive](/docs/concepts/guards)

## Interceptors

An interceptor wraps a controller method call — "around advice" resolved from the DI container.
Call `next()` to run the handler (or the next interceptor); whatever you return becomes the new
result.

```typescript
import { Service } from 'nextrush/class';
import type { Interceptor } from 'nextrush/class';
import type { Context } from '@nextrush/types';

@Service()
class TimingInterceptor implements Interceptor {
  async intercept(ctx: Context, next: () => Promise<unknown>) {
    const start = Date.now();
    const result = await next();
    ctx.set('X-Response-Time', `${Date.now() - start}ms`);
    return result;
  }
}
```

[Interceptors → deep dive](/docs/concepts/interceptors)

## Exception filters

An exception filter declares, via `@Catch(...)`, which error types it handles, and turns a thrown
error into a response scoped to one controller or route — everything else keeps using the
application's default error handler.

```typescript
import { Catch, Service } from 'nextrush/class';
import type { ExceptionFilter } from 'nextrush/class';
import type { Context } from '@nextrush/types';
import { NotFoundError } from 'nextrush';

@Service()
@Catch(NotFoundError)
class NotFoundFilter implements ExceptionFilter {
  catch(error: unknown, ctx: Context): void {
    ctx.status = 404;
    ctx.json({ error: 'Resource not found' });
  }
}
```

[Exception filters → deep dive](/docs/concepts/exception-filters)

## Lifecycle hooks

A `@Service`, `@Repository`, or controller class can implement `OnInit` / `OnShutdown` by
declaring the matching method — no decorator required. `onInit` runs once at boot in dependency
order; `onShutdown` runs once at shutdown in the exact reverse order.

```typescript
import type { OnInit, OnShutdown } from 'nextrush/class';
import { Service } from 'nextrush/class';

@Service()
class DatabaseService implements OnInit, OnShutdown {
  async onInit() {
    // open the connection pool
  }
  async onShutdown() {
    // close the connection pool
  }
}
```

[Lifecycle hooks → deep dive](/docs/concepts/lifecycle)

## Adapters

Your application code — routes, middleware, controllers — stays the same across runtimes. Only
the adapter changes.

```typescript
import { listen } from 'nextrush'; // Node.js (default)
await listen(app, 8080);

// Edge has no listen() — export a fetch handler instead:
// import { createFetchHandler } from '@nextrush/adapter-edge';
// export default { fetch: createFetchHandler(app) };
```
