# README.md (root)

## Summary
NextRush: minimal, modular, high-performance Node.js framework. Core under 3,000 LOC, zero runtime dependencies, TypeScript-strict, competes with Fastify/Hono/Koa. Ships a meta package (`nextrush`) re-exporting essentials, plus install-separately middleware/extensions/class-based packages.

## Key Takeaways
- **Performance claims are currently withdrawn pending re-measurement** on a clean CPU-pinned environment — prior numbers came from a shared machine, non-reproducible. `apps/benchmark` has a hardened, parity-validated harness (`pnpm bench:validate` for fairness, `pnpm bench:compare --profile full` for publishable 5-run numbers).
- Two primary usage styles: functional (`createApp`, `createRouter`, `app.route()`) and class-based (`@Controller`, `@Get`, `@Service` from `nextrush/class`).
- Services are singleton by default; `transient` and `request` scopes available via `@Service({ scope })`. Request scope uses a per-request child DI container, bubbling automatically through the dependency graph.
- `@Module` composes controllers/providers/imports; `registerModule` reuses the `registerControllers` pipeline. **Modules group but do not yet encapsulate** — every provider is visible to every module regardless of `exports` (recorded, not enforced). True encapsulation is a planned follow-up (RFC-NEXTRUSH-MODULES.md).
- Context API (`ctx`) is the unified request/response interface — never raw req/res.
- Package catalog spans Core (5 pkgs), Middleware (11 pkgs), Extensions (2 pkgs, long-lived stateful services via `app.extend()`), more middleware/registrars (5 pkgs incl. static/template/logger/stream/openapi), class-based dev (5 pkgs, 2 deprecated shims), and dev tooling (2 pkgs).
- CLI: `nextrush dev`, `nextrush build`, `nextrush generate <type> <name>` (controller/service/middleware/guard/route generators).
- Versioning: SemVer + Changesets.

## Open Questions / Gaps Noted
- Module encapsulation (`exports` enforcement) not yet implemented — see RFC-NEXTRUSH-MODULES.md.
- Benchmark numbers are a moving target — anyone quoting throughput figures should re-run `apps/benchmark` rather than cite the README's historical claims.
